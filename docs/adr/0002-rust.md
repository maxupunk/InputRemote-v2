# ADR-0002 — Rust como linguagem do núcleo

**Status:** aceito · **Data:** 2026-09-09 · **Substitui:** nada

## Contexto

A escolha foi reaberta de propósito. O v1 era Rust e fracassou em manutenibilidade, então
a linguagem não podia ser assumida por inércia — precisava ser justificada de novo, contra
o requisito novo da tela de bloqueio.

Os quatro eixos e a comparação completa estão em [07, §1](../07-stack-e-dependencias.md).

## Decisão

Rust, edição 2024, para os três binários e todos os crates.

## Alternativa mais séria: C++

C++ é melhor no eixo de acesso a API nativa e tem bindings mais maduros para `libei`,
portais e BlueZ. Perde num ponto só, e é o ponto que decide.

O decodificador de protocolo roda como `SYSTEM`, processa bytes vindos de um rádio
Bluetooth que qualquer um pode alcançar, e faz isso **antes de haver qualquer usuário
logado**. Um estouro de buffer ali é execução remota de código com privilégio máximo, sem
autenticação, numa máquina bloqueada.

Em Rust, `#![forbid(unsafe_code)]` no crate do decodificador transforma isso numa
propriedade verificada pelo compilador. Em C++, seria uma intenção sustentada por
disciplina de revisão. Para este componente, a diferença entre garantia e intenção é o
argumento inteiro.

## Outras alternativas

**C# / .NET.** Produtividade excelente em Windows e as melhores APIs de Bluetooth WinRT.
Reprova em dois eixos: um runtime gerenciado carregando na tela de login é frágil e lento
para subir, e o coletor de lixo introduz pausas justamente no caminho do ponteiro, onde a
meta é p99 previsível. Fecha a porta para o Linux.

**Go.** Reprova pelo coletor de lixo e porque `CreateProcessAsUser`, `SendInput`, ganchos
de baixo nível e `ioctl` de `uinput` viram `syscall` verboso ou `cgo` — perdendo a
simplicidade que seria a razão de escolhê-lo.

**Zig.** Atende os eixos técnicos, mas a linguagem ainda muda entre versões e não há
ecossistema de D-Bus, BlueZ, portais ou `libei`. Seria construir tudo do zero.

## Consequências

**Boas.**
- Segurança de memória onde ela vale mais, sem custo em tempo de execução.
- Binário estático, sem runtime, subindo cedo no boot.
- Sem coletor de lixo: latência p99 é função do código, não do alocador.
- Um código só para os dois sistemas.
- `Cargo` dá teste, lint, auditoria de dependências e fuzzing sem infraestrutura extra.

**Ruins, e aceitas.**
- Os *backends* de plataforma continuam precisando de `unsafe`; Rust confina o risco,
  não o elimina ([09, §4](../09-padroes-de-codigo.md)).
- Compilação mais lenta que Go, comparável a C++.
- Bindings de `libei`, portais e BlueZ menos maduros que os de C — mitigado por PoC antes
  de cada etapa que depende deles.
- **A linguagem não protege contra arquitetura ruim.** O v1 provou isso com 4.545 linhas
  em um arquivo. É por isso que [ADR-0004](0004-nucleo-sans-io.md) e
  [09](../09-padroes-de-codigo.md) existem, e por que os limites são verificados pelo CI
  em vez de combinados.
